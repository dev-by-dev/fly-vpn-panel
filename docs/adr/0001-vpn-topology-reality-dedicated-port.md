# ADR-0001: VPN topology — Reality on dedicated port, UI behind existing reverse proxy

**Date**: 2026-11-20
**Status**: accepted
**Deciders**: владелец продукта (выбор A) + агент-оператор

## Context

На сервере уже работает действующий VPN-стек: общий reverse proxy Caddy занимает 80/443 и обслуживает существующую панель. Новая панель должна сосуществовать, не ломая существующий канал. Reload общего Caddy рвёт ВСЕ established-соединения всех сайтов. Хочется полный контроль над xray-конфигом без прослойки.

## Decision

Топология A: VPN = VLESS + XHTTP + **Reality на выделенном порту** (дефолт 8443), xray сам терминирует TLS — домен/сертификат для VPN не нужны. UI и подписки — за существующим Caddy на новом поддомене `<PANEL_DOMAIN>`, один аддитивный блок `reverse_proxy <DOCKER_GW>:3002`. Вход VPN — `<ENTRY_IP>`, исход трафика — `<EGRESS_IP>` (sendThrough).

## Alternatives Considered

### Alternative 1: B — всё за существующим Caddy (как действующий канал)
- **Pros**: один порт 443, не нужно открывать новый.
- **Cons**: h2c-прослойка между Caddy и xray; новый VPN зависит от reload/inode-ловушек общего Caddy; не «полный контроль над конфигом».
- **Why not**: связывает жизненный цикл нового VPN с чужим прокси — именно та сложность, от которой уходим.

### Alternative 2: C — второй Caddy на 8443 + LE DNS-01
- **Pros**: TLS-терминация привычным прокси, изоляция от общего Caddy.
- **Cons**: лишняя сущность (второй прокси), сертификаты через DNS-01 API, возня с продлением.
- **Why not**: Reality даёт TLS без сертификатов вообще — второй Caddy не нужен.

## Consequences

### Positive
- VPN-канал независим от Caddy: reload прокси не рвёт VPN-сессии.
- Нет домена/сертификата для VPN (Reality маскируется под dest-сайт).
- Минимальное изменение общего прокси: один аддитивный блок.

### Negative
- Ещё один публичный порт (8443) — правило firewall.
- UI всё равно зависит от общего Caddy (reload-окно).

### Risks
- Reload Caddy при деплое рвёт established-соединения всех сайтов → тихое окно + явное разрешение оператора + верификация runtime-конфига.
- Reality dest должен быть доступен из клиентской сети и поддерживать TLS1.3+H2 → дефолт www.microsoft.com:443, конфигурируемый.
