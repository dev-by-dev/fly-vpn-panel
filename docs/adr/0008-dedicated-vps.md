# ADR-0008: Dedicated VPS instead of coexistence

**Date**: 2026-11-20
**Status**: accepted
**Deciders**: владелец продукта (инициатива) + агент-оператор

## Context

Исходный дизайн предполагал сосуществование: новая панель на том же сервере, что и действующий прод VPN-стек (общий Caddy, docker-сеть, занятые порты). Риски: reload Caddy рвёт соединения всех сайтов (включая SSH оператора через туннель), bind-inode ловушка, общие порты, правки firewall рядом с продом. Пользователь предложил поднять отдельную VPS. Разведка подтвердила достаточность минимальной конфигурации: 1 vCPU / 1 GB RAM / 10 GB disk, Ubuntu 24.04, один публичный IP, порты 80/443/8443/3002/10811 свободны, swap отсутствует.

## Decision

Новая панель разворачивается на **выделенной VPS** (1 vCPU / 1 GB / 10 GB, один IP, вход=выход). Старый сервер при деплое не затрагивается вообще. Caddy — нативная установка с нуля, панель bind `127.0.0.1:3002`, swapfile 2 GB, Docker не нужен. `sendThrough` опускается (один IP); поле `<EGRESS_IP>` сохранено как задел на будущее «вход≠выход».

## Alternatives Considered

### Alternative 1: Coexist на старом сервере (исходный план)
- **Pros**: не нужен новый сервер, DNS уже указывает туда.
- **Cons**: риск для прод-стека (reload рвёт все соединения, включая SSH оператора), тихие окна, docker-gateway bind, общие порты/firewall.
- **Why not**: пользователь выбрал изоляцию; стоимость дешёвой VPS ниже риска сломать работающий канал.

## Consequences

### Positive
- Изоляция by construction: деплой физически не может сломать действующий стек.
- Свой Caddy: без inode-ловушек и тихих окон, простой откат.
- Проще топология: loopback bind, без docker-сети, без регрессии старого стека.

### Negative
- Дополнительный сервер (стоимость, администрирование).
- DNS: A-запись `<PANEL_DOMAIN>` нужно перенаправить на новый IP при деплое.
- Миграция юзеров со старой панели — отдельная задача потом.

### Risks
- 1 GB RAM: обязателен swap 2 GB; сборка на машине оператора (cross-compile), не на VPS.
- Агент провайдера занимает 8080/8189 — не трогать.
- Один IP: при будущем «вход≠выход» добавить второй IP и задать `<EGRESS_IP>` (генератор уже поддерживает).
