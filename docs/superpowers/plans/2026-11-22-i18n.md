# i18n (ru / en / de) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every interface string in the panel comes from a dictionary, with a `RU / EN / DE` switcher in the header; default `ru`.

**Architecture:** One `$state` language store plus three flat dictionaries; `t()` is a plain function reading the reactive store, so templates re-render on switch. `en.ts`/`de.ts` are typed against `keyof typeof ru`, making a missing translation a compile error. Backend stays untouched: error codes are mapped to keys on the frontend.

**Tech Stack:** Svelte 5 runes, TypeScript, Vitest + @testing-library/svelte.

**Spec:** `docs/superpowers/specs/2026-11-22-i18n-design.md`

## Global Constraints

- Language persisted only in `localStorage` under key `lang`, values `ru|en|de`.
- First visit: `navigator.language` starting with `ru` → `ru`, `de` → `de`, anything else → `en`. Unknown stored value → `ru`.
- Default in tests is `ru` (global setup), so all 34 existing tests keep asserting Russian.
- Key naming: `<area>.<meaning>` with areas `nav`, `common`, `login`, `dashboard`, `users`, `inbounds`, `templates`, `config`, `settings`, `traffic`, `errors`.
- Values move verbatim into `ru.ts`; `en.ts` and `de.ts` must have the same keys.
- Interpolation uses `{name}` placeholders; no plural rules — word counts so no noun declension is needed.
- No new npm dependencies. No visual redesign: same markup, only text sources change.
- Server-provided free text (usernames, tags, UA, country) is never translated. Dates keep `toLocaleDateString('ru-RU')`.

## Review Focus

- Switching language must not lose unsaved input (Settings token form, Config textarea, dialog fields).
- A missing key must be loud: `t()` returns the key itself only as a last resort, and the type makes it a compile error first.
- Error texts that came from backend codes must stay meaningful in all three languages, including unknown codes (fallback shows the code, not an empty string).
- `localStorage` may throw (private mode / disabled storage): switching language must still work for the session.
- Tests that look up elements by Russian text must keep working under `lang=ru` defaults.

**Interfaces:**
- Produces:
  ```ts
  export type Lang = 'ru' | 'en' | 'de';
  export type Key = keyof typeof ru;
  export const i18n: { lang: Lang };
  export function t(key: Key, vars?: Record<string, string | number>): string;
  export function setLang(lang: Lang): void;
  ```

- [ ] **Step 1: Write failing tests**

`web/src/lib/i18n.test.ts`: `t('nav.dashboard')` returns `'Главная'` with `lang='ru'`; after `setLang('en')` returns `'Home'`; `setLang('de')` returns the German string; `t('common.onlineCount', { n: 3 })` substitutes `3`; an unknown stored value (`localStorage.setItem('lang','xx')` then fresh import via `vi.resetModules()`) falls back to `ru`; `setLang` persists to `localStorage`.

`web/src/App.test.ts`: render `App`, assert nav link text `Юзеры`; click button `EN`; assert link text `Users` and that the RU button loses its active class.

- [ ] **Step 2: Run to verify failure** — `cd web && npx vitest run src/lib/i18n.test.ts src/App.test.ts` → FAIL (module missing).

- [ ] **Step 3: Implement**

`i18n.svelte.ts`: resolve initial language (`stored ?? detectFromNavigator() ?? 'ru'`, stored values validated against the three codes, `localStorage` access wrapped in try/catch), export `i18n = $state({ lang })`, `t()` (dictionary lookup → `ru` fallback → key; then `{var}` replacement), `setLang()` (set state, best-effort persist).

`locales/ru.ts` starts with `nav.*` (dashboard, users, inbounds, templates, settings, config), `common.*` (online, offline, save, cancel, delete, edit, copy, copied, refresh, loading, error, never, revoke, revoked, create, close) and `login.*` strings. `en.ts`/`de.ts`: `const en: Record<keyof typeof ru, string> = { … }`.

`test-setup.ts`: top-level `localStorage.setItem('lang', 'ru')`. `vitest.config.ts`: `test.setupFiles: ['./src/test-setup.ts']`.

`App.svelte`: `nav` labels become keys (`labelKey: 'nav.dashboard'` etc.) rendered with `t(...)`; header gains `<div class="flex items-center gap-1">` with three buttons, classes `rounded-md px-2 py-1 text-xs` plus `bg-sky-500/15 text-sky-300` when active, `onclick={() => setLang('ru')}` etc.
