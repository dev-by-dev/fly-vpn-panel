# Panel localization (ru / en / de) — design

**Date:** 2026-11-22
**Status:** accepted

## Why

The panel is currently fully Russian. English and German are needed for non-RU admins. Language is a property of the browser, not the server: the panel is single-user, so no server-side locale settings are required.

## Decisions (agreed with the user)

1. **Storage:** only `localStorage` (`lang` = `ru|en|de`). On the first visit — `navigator.language` if it is `ru*`/`de*`, otherwise `en`. Fallback for an unknown saved value — browser detection again; a missing key falls back to `ru`.
2. **Scope:** we translate the UI only. The backend is untouched: it returns error codes (`invalid_token_request`, `broken_template`, …) and the frontend maps them to texts. Russian messages coming from the backend as free text are shown as is.
3. **Switcher:** in the `App.svelte` header next to the navigation, three buttons `RU / EN / DE`, the active one highlighted. Available on every page, including login.
4. **Default ru** for the existing tests: the global test setup sets `lang=ru` before importing components.

## Approach

Our own mini-module, no dependencies:

- `web/src/lib/i18n.svelte.ts` — a `$state` object with `lang`, a `t(key, vars?)` function, `setLang(lang)`; `{name}` placeholder substitution.
- `web/src/lib/locales/{ru,en,de}.ts` — flat `Record<string,string>` dictionaries.
- `en.ts` and `de.ts` are typed as `Record<keyof typeof ru, string>`: a forgotten key is a compile error, not an empty string in the UI.
- Keys by page: `nav.*`, `common.*`, `login.*`, `dashboard.*`, `users.*`, `inbounds.*`, `templates.*`, `config.*`, `settings.*`, `traffic.*`.

Rejected: `svelte-i18n`/`typesafe-i18n` (a dependency for 330 lines), keeping the language in the `settings` table (an extra API and migration, and the language is not shared across browsers).

## What we translate

All visible strings in: `App.svelte`, `routes/{Login,Dashboard,Users,Inbounds,Templates,Config,Settings}.svelte`, `lib/components/{UserDialog,InboundForm}.svelte`, `lib/traffic.ts`, `lib/{usersIntent,inboundsIntent,auth.svelte}.ts`.

Not translated: data values from the server (usernames, inbound tags, UA, countries), date/number formatting (`dateTag()` picks `ru-RU` / `en-GB` / `de-DE`; this is not interface text), xray config texts.

## Non-goals

- Detecting the language by IP/geolocation.
- Server-side language rendering, SEO.
- Pluralization by language rules: wording is chosen without declined numerals (e.g. a “online: 3” style counter instead of “3 devices online”).
- Translating messages the backend sends as free text.

## Verification

- `cd web && npx vitest run` — 34 existing tests green (ru default).
- New tests: `i18n.test.ts` (navigator default, switching, placeholder substitution, fallback to ru), a header test (clicking EN switches the UI to English), a test for mapping an error code to a text.
- `svelte-check` — 0 errors.
- Manual check in a browser: switching to EN/DE on every page, a reload keeps the language.
