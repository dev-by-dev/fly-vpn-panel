# Локализация панели (ru / en / de) — дизайн

**Дата:** 2026-11-22
**Статус:** принято

## Зачем

Панель сейчас полностью русская. Нужны английский и немецкий для не-RU админов. Язык — свойство браузера, а не сервера: панель однопользовательская, серверных настроек локали не требуется.

## Решения (согласованы с пользователем)

1. **Хранение:** только `localStorage` (`lang` = `ru|en|de`). При первом заходе — `navigator.language`, если это `ru*`/`de*`, иначе `en`. Fallback при неизвестном сохранённом значении — `ru`.
2. **Объём:** переводим только UI. Бэкенд не трогаем: он отдаёт коды ошибок (`invalid_token_request`, `broken_template`, …), фронтенд маппит их в тексты. Русские сообщения из бэкенда, приходящие как свободный текст, показываются как есть.
3. **Переключатель:** в шапке `App.svelte` рядом с навигацией, три кнопки `RU / EN / DE`, активная подсвечена. Доступен со всех страниц, включая логин.
4. **Дефолт ru** для существующих тестов: глобальный тестовый setup выставляет `lang=ru` до импорта компонентов.

## Подход

Свой мини-модуль, без зависимостей:

- `web/src/lib/i18n.svelte.ts` — `$state`-объект с `lang`, функция `t(key, vars?)`, `setLang(lang)`; подстановка `{name}`-плейсхолдеров.
- `web/src/lib/locales/{ru,en,de}.ts` — плоские словари `Record<string,string>`.
- `en.ts` и `de.ts` типизированы как `Record<keyof typeof ru, string>`: забытый ключ — ошибка компиляции, а не пустая строка в UI.
- Ключи по страницам: `nav.*`, `common.*`, `login.*`, `dashboard.*`, `users.*`, `inbounds.*`, `templates.*`, `config.*`, `settings.*`, `traffic.*`.

Отклонено: `svelte-i18n`/`typesafe-i18n` (зависимость ради 330 строк), хранение языка в таблице `settings` (лишний API и миграция, язык не общий для всех браузеров).

## Что переводим

Все видимые строки в: `App.svelte`, `routes/{Login,Dashboard,Users,Inbounds,Templates,Config,Settings}.svelte`, `lib/components/{UserDialog,InboundForm}.svelte`, `lib/traffic.ts`, `lib/{usersIntent,inboundsIntent,auth.svelte}.ts`.

Не переводим: значения данных с сервера (имена юзеров, теги инбаундов, UA, страны), формат дат/чисел (`toLocaleDateString('ru-RU')` остаётся как есть — это не текст интерфейса), тексты xray-конфига.

## Не-цели

- Определение языка по IP/геолокации.
- Серверный рендер языка, SEO.
- Плюрализация по правилам языка: формулировки выбираем без склоняемых числительных («онлайн: 3» вместо «3 устройства онлайн»).
- Перевод сообщений, которые бэкенд присылает свободным текстом.

## Проверка

- `cd web && npx vitest run` — 34 существующих теста зелёные (дефолт ru).
- Новые тесты: `i18n.test.ts` (дефолт по navigator, переключение, подстановка плейсхолдеров, fallback на ru), тест шапки (клик EN меняет `Добавить` → `Add`), тест маппинга кода ошибки на текст.
- `svelte-check` — 0 ошибок.
- Ручная проверка в браузере: переключение на EN/DE на каждой странице, перезагрузка сохраняет язык.
