# Routing уезжает во вкладку «Конфиг»

## Зачем

Вкладка Routing — единственное место, где правится серверная секция `routing`
xray (блок-лист + `domainStrategy`). В генерируемом конфиге есть только
аутбаунды `direct` и `block`, поэтому полноценного «прокси наружу» там нет и
экран узкий по смыслу. Как верхняя вкладка рядом с семью другими он занимает
место, но нужен редко.

## Что делаем

1. Убрать `Routing` из верхнего nav и из таблицы маршрутов в `App.svelte`.
2. `Routing.svelte` удалить; его редактор (textarea + «Проверить» + «Применить»,
   тот же warning про мгновенное применение и откат) перенести в конец
   `Config.svelte` отдельной секцией «Routing (advanced JSON)».
3. Старые закладки `#/routing` вести на Config: оставить в таблице маршрутов
   `'/routing': Config` — одна строка, страница не пустеет.
4. Бэкенд не трогаем: `/api/config/routing` GET/PUT остаются как есть.

## Границы

- Не добавляем пресеты правил и валидацию схемы — только перенос.
- Не меняем вид генератора конфига и дефолт `{"domainStrategy":"AsIs","rules":[]}`.
- Config грузит обе ручки параллельно, ошибки секций независимы: не смог
  загрузиться routing — генеральный конфиг всё равно показывается.

## Проверка

- `web`: новый `Config.test.ts` — routing грузится, PUT уходит с текстом из
  textarea, 422 показывает сообщение об откате.
- `go test ./...` и `make web-test` зелёные; `make build` собирается.
