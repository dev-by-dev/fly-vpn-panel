# Спецификация: HWID и данные устройства из заголовков клиента

## Контекст

Сейчас панель знает только имя пользователя и IP-адрес источника (это всё, что
отдаёт xray). В «HWID / устройства» платформа, версия, модель и User-Agent
показываются как «—». В Remnawave эти поля заполняются потому, что клиент сам
присылает их заголовками при запросе подписки.

Клиенты Happ, INCY, v2rayNG и mihomo-совместимые при fetch подписки отправляют:

| Заголовок | Значение |
|---|---|
| `X-HWID` | идентификатор устройства от клиента |
| `X-Device-OS` | `Windows` / `iOS` / `Android` / `macOS` / `Linux` |
| `X-Device-Model` | модель (`iPhone 15 Pro`, `SM-S938B`, `DESKTOP-…`) |
| `X-Ver-OS` | версия ОС (`11_10.0.26100`, `17.2`) |
| `User-Agent` | клиент и версия (`Happ/4.8.1/Windows/…`) |

Проверено на наших клиентах: инбаунд-панель уже видит эти запросы, но заголовки
не сохраняет.

## Цель

Показывать в «HWID / устройства» реальные HWID, платформу, версию ОС, модель и
User-Agent вместо «—», а в таблице пользователей — количество устройств (уже
есть, колонка Σ).

## Решение

### Хранилище

Миграция `0002_device_headers.sql` — в `devices` добавить nullable-колонки:

```sql
ALTER TABLE devices ADD COLUMN hwid TEXT NOT NULL DEFAULT '';
ALTER TABLE devices ADD COLUMN platform TEXT NOT NULL DEFAULT '';
ALTER TABLE devices ADD COLUMN os_version TEXT NOT NULL DEFAULT '';
ALTER TABLE devices ADD COLUMN model TEXT NOT NULL DEFAULT '';
ALTER TABLE devices ADD COLUMN user_agent TEXT NOT NULL DEFAULT '';
```

`store.Device` получает соответствующие поля; `DeviceUpsert` расширяется до
`DeviceUpsert(username, ip string, meta DeviceMeta, now time.Time)`, где пустые
поля не затирают ранее сохранённые значения (клиент может прислать не всё).

### Сбор

В `sub.Handlers.Sub` (перед отдачей подписки):

1. IP берём из `X-Forwarded-For` **только** если запрос пришёл с loopback
   (Caddy → 127.0.0.1:3002), иначе `RemoteAddr`. Иначе заголовок подделывается.
2. Читаем `X-HWID`, `X-Device-OS`, `X-Ver-OS`, `X-Device-Model`, `User-Agent`
   (обрезаем до 256 символов).
3. Пишем в `devices` для пользователя подписки — независимо от того, онлайн он
   по xray или нет.
4. Ошибки записи логируем, но подписку не ломаем.

### API

`GET /api/devices` уже отдаёт `Username, IP, FirstSeen, LastSeen, online` —
добавляем `hwid, platform, os_version, model, user_agent`.

### UI

В панели «HWID / устройства» колонки заполняются из API; при пустом значении —
«—». Подпись «xray отдаёт только имя и IP…» убирается.

## Безопасность и приватность

- Заголовки — данные клиента, доверять им нельзя: используются только для
  отображения, не для авторизации и не для лимитов.
- `X-Forwarded-For` принимается только от loopback-прокси.
- Длины ограничены, в HTML попадают через обычный экранированный вывод Svelte.

## Проверка

- store-тест: upsert с заголовками заполняет поля; повторный upsert без
  заголовков не стирает их; новый IP создаёт строку.
- sub-тест: `GET /sub/{token}` с набором заголовков пишет устройство; без
  заголовков — только IP.
- API-тест: `/api/devices` содержит новые поля.
- Ручная проверка: импорт подписки в Happ/INCY на планшете → в панели появились
  HWID, платформа, модель, UA.
- `go test ./...`, `npm run check`, `npx vitest run`.

## Вне рамок

- Лимит устройств по HWID вместо IP (`device_limit` остаётся по IP).
- История смены устройств, блокировка по HWID, геолокация.
- Заголовки, которые клиент не прислал, — остаются пустыми.
