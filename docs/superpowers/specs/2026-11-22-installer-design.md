# flypanel end-user installer — design

Date: 2026-11-22

## Why

Today the panel is installed following `docs/deploy-checklist.md`: user, directories, xray with `.dgst` verification, `.env`, systemd unit, UFW, Caddy, DNS, `admin init`. That is an operator playbook, not an install for someone who bought a VPS and wants a panel.

Goal: one bash script on a clean Ubuntu 22.04/24.04 or CentOS Stream that installs everything itself and asks only what it cannot know: language, domain, e-mail for Let's Encrypt, admin login. The admin password is generated by the script (16 random alphanumerics from `/dev/urandom`) and the admin is created non-interactively via `flypanel admin init --password-stdin`; the final summary prints the password once.

## What was decided (option A)

One idempotent `install.sh`, root on the VPS. Options B (`curl | bash`) and C (Docker) rejected: B is the same script but with the bad practice of executing code from the network (we publish the file anyway, people can download and read it); C breaks “Monitoring → Logs” (no journald), the panel spawns xray inside the container, systemd/UFW are bypassed.

Product owner decisions (“your call everywhere”):

1. **Caddy — the official static binary from GitHub Releases + our own systemd unit.** No third-party apt keys. Cost: manual Caddy updates.
2. **DNS strict.** If the domain's A record does not point to this IP yet, the script stops before any changes and prints what to set at the registrar. The workaround is `--skip-dns` (deliberate, for “install first, DNS later”).
3. **Coverage: Ubuntu 22.04/24.04 and CentOS Stream 9/10, amd64.** Debian, RHEL clones (Rocky, Alma), arm64, Windows, Docker — not supported at launch, added on demand. CentOS 7/8 unsupported: EOL, the script refuses with a clear message.

## Prerequisite: releases

The script downloads the panel from GitHub Releases, and there are none yet: `main` is at `Initial commit`, `dev` is 46 commits ahead.

Order:

1. Merge `dev` into `main`, push (right now `main` in origin is behind).
2. Add `.github/workflows/release.yml`: on a `v*` tag — checkout, Node 20, Go from `go.mod` (1.27), `make cross`, `sha256sums.txt`, create a release with the `flypanel-linux-amd64`, `install.sh`, `sha256sums.txt` assets. The repo is public, Actions are free.
3. Tag `v0.1.0` — the first release, and the one the script is tested on.

Further releases — a tag and a push of the tag. The panel version is not shown in the UI (out of scope).

## Script

File `scripts/install.sh`, also a release asset. Published at `https://raw.githubusercontent.com/dev-by-dev/fly-vpn-panel/main/scripts/install.sh` and as `releases/latest/download/install.sh`.

### Skeleton

- `set -euo pipefail`, log to `/var/log/flypanel-install.log` (everything duplicated through `tee`), colors only on a tty.
- `trap` on `ERR`: prints the command, line number, path to the log. No rollback — the script is idempotent, a re-run catches up.
- Arguments: `--lang ru|en|de`, `--domain`, `--email`, `--admin`, `--ip`, `--yes`, `--dry-run`, `--skip-dns`, `--skip-firewall`, `--no-update`, `--force` (for containers and unsupported OS), `-h`. Without flags — interactive.
- `--dry-run`: prints every action without making changes (for checking on someone else's machine).
- A `flock` lock on `/run/lock/flypanel-install.lock`: a concurrent second run exits, so two runs cannot race on apt or scramble the log.

### Language

The first question is the language prompt (`[1] ru [2] en [3] de`), defaulted from `$LANG` (`de*`→de, `en*`→en, otherwise ru). Three parallel associative arrays `MSG_RU/MSG_EN/MSG_DE` with named keys and a `t key` function. No gettext or external files: the script must work as a single file.

Translations cover: welcome, questions, preflight warnings, install steps, the final summary, the error text.

### Preflight (before any changes)

Checks, each with a clear message and an exit: root; `x86_64`; systemd (`/run/systemd/system`); a supported OS from `/etc/os-release` — `ID=ubuntu` + `VERSION_ID` 22.04/24.04 → `apt` family, or `ID=centos` + `VERSION_ID` 9/10 → `dnf` family; everything else (Debian, Rocky, Alma, CentOS 7/8, arm64) — refusal with the text “Ubuntu 22.04/24.04 and CentOS Stream 9/10 are supported; for other systems install manually per docs/deploy-checklist.md”, workaround only `--force` (no guarantees); `curl`, `unzip`, `iproute`/`ss` available or installed by the family package manager; disk ≥ 2 GB free in `/opt`; ports 80, 443, 8443, 3002, 10811 free; not in a container (`/.dockerenv`, `systemd-detect-virt --container`), otherwise `--force`.

The OS family is one variable (`FAMILY=apt|dnf`), and packages, firewall and SELinux are chosen from it. The common part (user, directories, binary, xray, `.env`, systemd, Caddy, HTTPS check) does not depend on the family.

IP detection: `curl -4 -fsS https://api.ipify.org` (fallback `https://ifconfig.co`), or `--ip`. Cross-check with `ip -4 addr` — if the IP is not local, warn (NAT/proxy).

DNS check: `getent hosts <domain>` (fallback DoH `https://dns.google/resolve?name=...&type=A`), compare with the IP. Mismatch → exit with instructions. `--skip-dns` skips it.

Memory: if RAM < 2 GB and there is no swap — create a 2 GB `/swapfile` (a step from the checklist), otherwise skip.

### Questions (after preflight, unless `--yes` + flags)

1. Panel domain — required, validation `^[a-z0-9.-]+\.[a-z]{2,}$`, refuse `<...>` and `example.com`.
2. E-mail for Let's Encrypt — may be empty (the certificate is still issued, expiry notices just will not arrive).
3. Admin login — default `admin`.
4. Open ports in the firewall? — default yes (22/80/443/8443; the SSH port is taken from `sshd -T | grep ^port`, default 22; the 22 rule is added BEFORE the firewall is enabled). UFW on Ubuntu, firewalld on CentOS.

Final screen: domain, IP, e-mail, login, what will be installed. Confirmation `[Y/n]`.

### Install steps (each idempotent)

1. System update, then the family packages: Ubuntu — `apt-get update` + `apt-get -y upgrade` (otherwise a fresh machine keeps a year-old kernel and openssl), then `curl ca-certificates unzip ufw iproute2`; CentOS — `dnf -y upgrade --refresh`, then `dnf install -y curl ca-certificates unzip firewalld policycoreutils-python-utils iproute`, `systemctl enable --now firewalld` (skipping what is already installed). `--no-update` skips the update half; the package half always runs.
2. User `flypanel` (system, home `/opt/flypanel`, nologin) and the `bin data logs backups` directories — if the user does not exist; existing directories are not touched. The packages this run added are recorded in `/opt/flypanel/installed-packages`, which the uninstaller reads.
3. Panel: `releases/latest/download/flypanel-linux-amd64` + `sha256sums.txt`, checksum verification, atomic install — download to `bin/flypanel.new`, `chown`/`chmod 755`, `mv` over `bin/flypanel` (writing over a running binary gives `ETXTBSY`), then `systemctl restart flypanel`.
4. xray: version pinned `XRAY_VERSION=26.11.9`, asset `Xray-linux-64.zip` + `.zip.dgst`, verify `SHA2-256=`, unpack `xray geoip.dat geosite.dat` into `bin/`. If `bin/xray` already exists with another version — warn and do not overwrite without `--force`.
5. `/opt/flypanel/.env` (600, owner flypanel): `LISTEN_ADDR=127.0.0.1:3002`, `DATA_DIR=/opt/flypanel/data`, `XRAY_BIN=/opt/flypanel/bin/xray`, `ENTRY_IP=<IP>`, `EGRESS_IP=`, `PANEL_DOMAIN=<domain>`, `POLL_INTERVAL_SEC=30`, `COOKIE_SECURE=true`. If the file already exists — back it up to `.bak-YYYYMMDDHHMM` and rewrite from the answers.
6. `chown -R flypanel:flypanel /opt/flypanel`.
7. systemd unit exactly as in the checklist (including `PrivateTmp=true`, `ProtectSystem=strict`, `ReadWritePaths=/opt/flypanel`, `SupplementaryGroups=systemd-journal`, `Restart=on-failure`); `daemon-reload`, `enable --now flypanel`.
8. Firewall (only if the user agreed): Ubuntu — `ufw allow <ssh>/tcp`, 80, 443, 8443, then `ufw --force enable`; CentOS — `firewall-cmd --permanent --add-port=` for the same ports, `firewall-cmd --reload`. The SSH port is added first.
9. SELinux (CentOS only, if `getenforce` = Enforcing): after the panel and Caddy start, check `ausearch -m avc -ts recent`; on port denials — `semanage port -a -t http_port_t -p tcp 8443` and `3002` (if the port already carries another label — `-m`), then `systemctl restart caddy flypanel`. The units are ours, so normally the domain is `unconfined_service_t` and there are no denials; the step covers the case where the policy has been tightened.
10. Caddy: version pinned `CADDY_VERSION=2.11.9`, `caddy_2.11.9_linux_amd64.tar.gz` + verification against the `SHA512` from `caddy_2.11.9_checksums.txt`; binary at `/usr/local/bin/caddy`, user `caddy` (system), directories `/etc/caddy` (root) and `/var/lib/caddy` (caddy); systemd unit `caddy.service` with `ExecStart=/usr/local/bin/caddy run --environ --config /etc/caddy/Caddyfile`, `Environment=XDG_DATA_HOME=/var/lib/caddy/.local/share`; `/etc/caddy/Caddyfile`:
   ```
   {
       metrics
   }

   <domain> {
       log
       reverse_proxy 127.0.0.1:3002
   }
   ```
   An existing Caddyfile → backup; if it already has `<domain>` — do not duplicate the block. `caddy validate`, `systemctl enable --now caddy` (or `reload` if it is already running).
11. Wait: up to 90 s for `curl -fsS https://<domain>/` → 200 with `assets/index-` in the body. On timeout: if the panel already answers 200 on `http://127.0.0.1:3002/`, print a warning that the certificate is not ready yet (Caddy keeps retrying) and continue; otherwise print `journalctl -u caddy -n 20` and exit with an error (DNS/port 80/ACME).
12. Admin: `runuser -u flypanel -- env FLYPANEL_ENV=/opt/flypanel/.env /opt/flypanel/bin/flypanel admin status` — code 0 means the admin exists, the step is skipped. Otherwise generate a 16-character alphanumeric password from `/dev/urandom` and pipe it into `runuser -u flypanel -- env FLYPANEL_ENV=/opt/flypanel/.env /opt/flypanel/bin/flypanel admin init --password-stdin <login>`.
13. Summary: panel URL, local URL (while the certificate is pending), login, the generated password (once, with a prompt to save it), where the logs are, `systemctl status`, how to update the panel (re-run the script), how to roll back (`docs/deploy-checklist.md` §8), where the backups are.

### What the script does NOT do

- Does not create DNS records, does not log in to the registrar.
- Does not touch the provider firewall or the SSH port in sshd.
- Does not delete data: `data/panel.db` and `data/backups` are never overwritten.
- Does not update itself, the panel, xray or Caddy automatically (a re-run updates the panel, but not xray/Caddy — their versions are pinned).
- Does not configure swap if RAM ≥ 2 GB.
- Does not install a second domain, a reverse proxy to other services, or monitoring agents.

## Boundaries

- Target OSes: Ubuntu 22.04/24.04 and CentOS Stream 9/10, amd64. Others — refusal with a text, `--force` without guarantees.
- Caddy listens on 80/443; xray — 8443 + loopback 10811; the panel — loopback 3002.
- Internet is required: apt/dnf, GitHub Releases (panel, xray, Caddy), Let's Encrypt.

## Verification

1. `bash -n scripts/install.sh`, `shellcheck` (if available locally).
2. `--dry-run` in `ubuntu:24.04` and `centos:stream9` containers with `--force` — prints all steps with the right family, creates no files.
3. A run on a clean VPS (candidate — `<host>`, where flypanel is inactive): language EN → install → HTTPS 200 → create a user → `/sub/<token>` in 4 formats → “Monitoring → Logs” and “Caddy” return data.
4. A re-run on the same machine: “everything is already installed”, data and admin intact, the panel restarted, the domain not duplicated in the Caddyfile.
5. A run on CentOS Stream 9 (a second clean VPS): language RU → install → HTTPS 200 → `firewall-cmd --list-ports` contains 80/443/8443 → `getenforce` and no fresh AVC.
6. Negative: wrong domain (DNS does not match) → stop before changes; port 80 busy → stop; run as non-root → a clear error in the chosen language.
## Clarifications after spec review

1. **Ports and re-runs.** Preflight looks at the owner via `ss -ltnp`: the port is free **or** held by our own processes (`flypanel`, `xray`, `caddy`) — the check passes. A foreign process on 80/443/8443/3002/10811 → exit with the process name. So a re-run on a working panel does not trip over its own ports.
2. **The “admin already exists” check.** `flypanel admin status` is added to the binary: it prints `admin exists` and exits with code 0 if an admin exists, otherwise “no admin” and code 1. No `sqlite3` dependency, we do not read WAL from outside. This is the only Go code change in the feature; it gets a test in `cmd/flypanel`.
3. **Flags.** `--dry-run` performs read-only checks and prints the steps without changing anything; in dry-run a DNS failure, a busy port, a container and an unsupported OS are warnings, not exits. `--force` lifts the OS/container/DNS/port blocks (for debugging and foreign systems) but does not disable the SSH port check. Each check is a separate function so the exception list is explicit.
4. **SSH port and firewall.** The port comes from `sshd -T`, on failure — from `ss -ltnp` for the `sshd` process. If neither yields a port, **the script does not enable the firewall** and exits with a message on how to open the ports manually (the `--skip-firewall` flag lets it continue without firewall setup). The script cannot lock itself out of SSH.
5. **Domain change on re-run.** The site block in the Caddyfile is wrapped in `# flypanel-managed begin` / `# flypanel-managed end` markers. A re-run replaces the marker contents with the new domain, the old block does not survive. If there are no markers and the file is not empty and has no block for the requested domain — exit: we do not touch someone else's config.
6. **Someone else's Caddyfile.** The global `{ metrics }` block is added only if there is no global block; if there is a foreign global block without `metrics` — exit with a text (manual merge), we do not edit it. An existing site on 80/443 that is not ours — exit: otherwise ACME and the HTTPS check would fail on a foreign site.
7. **Execution details.** The admin step goes through `runuser` (not `sudo`, which a minimal CentOS may lack). A failed `admin init` — a warning and exit code 1 at the end, the panel is already installed and running; a re-run generates a new password.
